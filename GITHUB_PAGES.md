# Публикация QR-Find в интернете

## Важное ограничение GitHub Pages
GitHub Pages размещает только статические файлы (HTML, CSS, JavaScript). Он не запускает Python/FastAPI и не предоставляет SQLite/постоянное хранилище файлов. Поэтому этот полный вариант QR-Find с регистрацией, загрузкой фото, сообщениями и QR-кодами нельзя целиком запустить только на GitHub Pages.

Если загрузить проект как есть на Pages, главная страница может открыться, но API, регистрация, личный кабинет и сохранение данных работать не будут.

## Рекомендуемый способ для полного сайта
1. Создайте репозиторий GitHub и загрузите в него папку `qr_find`.
2. Не загружайте `qrfind.db`, `.venv`, содержимое `uploads` и `.env` — они исключены через `.gitignore`.
3. Разверните FastAPI-приложение на хостинге, который поддерживает Python (например, Render или Railway).
4. Для постоянного хранения выберите постоянный диск для SQLite или подключите PostgreSQL. На временной файловой системе SQLite-база и фотографии могут пропасть после перезапуска/пересоздания сервиса.
5. Укажите секрет сессии через переменную окружения `QR_FIND_SECRET` и включите HTTPS.
6. Используйте публичный адрес развернутого backend-сайта. Именно этот домен должен попадать в QR-коды, чтобы они открывались с телефонов других людей.

## Если нужен именно GitHub Pages
Можно опубликовать на Pages только отдельную демонстрационную статическую версию без настоящих аккаунтов, базы данных и серверных функций. Для полноценного QR-Find нужен отдельный backend.
