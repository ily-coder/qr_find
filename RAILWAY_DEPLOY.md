# QR-Find — публикация на Railway

## Важно
Для этой версии используется SQLite в постоянном Railway Volume. Фотографии также хранятся в этом Volume. Без Volume данные могут исчезнуть при пересборке/перезапуске сервиса.

## 1. Загрузить проект в GitHub
1. Создайте публичный или приватный репозиторий `QR-Find`.
2. Загрузите в корень репозитория содержимое папки `qr_find` (файлы `app.py`, `requirements.txt`, папки `static` и т. д.). Не загружайте `.venv`, `qrfind.db`, пароли и пользовательские фотографии.
3. Убедитесь, что `app.py` и `requirements.txt` находятся в корне репозитория, а не во вложенной папке.

## 2. Создать сервис Railway
1. Откройте https://railway.com/ и войдите.
2. Нажмите `New Project` → `Deploy from GitHub repo`.
3. Подключите GitHub, выберите репозиторий `QR-Find`.
4. Дождитесь первого деплоя. Если Railway пока показывает ошибку из-за отсутствующей переменной, добавьте переменные ниже и перезапустите деплой.

## 3. Добавить постоянное хранилище
1. В проекте Railway откройте сервис QR-Find.
2. Откройте вкладку `Volumes` (или добавьте Volume через настройки сервиса).
3. Создайте Volume и задайте Mount Path строго `/data`.

## 4. Добавить переменные
Вкладка `Variables` → добавьте:

- `QR_FIND_DATA_DIR` = `/data`
- `QR_FIND_SECRET` = длинная случайная строка не менее 32 символов. Не публикуйте её и не отправляйте другим людям.

После добавления переменных нажмите Redeploy, если Railway не сделал это автоматически.

## 5. Получить публичную ссылку
Откройте `Settings` → `Networking` → `Generate Domain`. Railway выдаст адрес вида `https://....up.railway.app`.
Откройте его и проверьте регистрацию, вход, добавление вещи, загрузку фото, QR-код и отправку сообщения с публичной страницы.

## 6. Как обновлять сайт
Измените файлы локально, отправьте изменения в GitHub (`Commit changes` / `git push`). Railway автоматически выполнит новый деплой, если включено автоматическое развёртывание.

## Примечания
- GitHub Pages не нужен: он не запускает FastAPI. GitHub здесь хранит исходный код, Railway запускает приложение.
- Не удаляйте Volume и не меняйте Mount Path `/data`, иначе приложение не увидит прежнюю SQLite-базу и фотографии.
- Сделайте резервные копии Volume регулярно. Для проекта с большим количеством пользователей лучше перейти на PostgreSQL и отдельное объектное хранилище фотографий.
- Не публикуйте персональные данные пользователей, базу `qrfind.db`, содержимое `uploads` или секрет `QR_FIND_SECRET`.
